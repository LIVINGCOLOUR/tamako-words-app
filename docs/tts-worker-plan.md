# Cloudflare Worker TTS設計メモ

## 1. 目的

たまこさん専用PoCとして、クイズ終了時と復習完了時の短い声かけだけを外部TTS化する。本人が「またやりたい」と感じるかを短時間で確認することを目的にし、製品化前提の大きな設計にはしない。

現在はWeb Speech API fallbackで読み上げている。次の段階でElevenLabsなどの外部TTSや声クローンAPIを使う場合も、APIキーをブラウザに置かず、Cloudflare Worker側で管理する。

## 2. 対象範囲

対象にするもの:

- 通常クイズ終了時の声かけ
- 復習完了時の声かけ

対象にしないもの:

- 正解時の声かけ
- 不正解時の声かけ
- 英単語読み上げ
- 日本語単語読み上げ
- 問題文読み上げ
- ログイン機能
- 学習履歴保存
- 本格的な分析機能

## 3. 構成案

```text
ブラウザ
↓
Cloudflare Worker
↓
外部TTS API（例: ElevenLabs）
↓
音声データ返却
↓
ブラウザで再生
```

ブラウザは短い固定文言と用途だけをWorkerへ送る。Workerは環境変数またはSecretに保存したAPIキーで外部TTS APIを呼び、音声データをブラウザへ返す。

## 4. APIキー管理

- APIキーはフロントエンドに置かない。
- Cloudflare Workerの環境変数またはSecretで管理する。
- GitHubにはAPIキーをコミットしない。
- `.env` などのローカル秘密情報ファイルもコミットしない。
- Workerのコード内にもAPIキーを直書きしない。

## 5. 最小API案

Worker側エンドポイント案:

```text
POST /api/tts/encouragement
```

リクエスト例:

```json
{
  "type": "finish",
  "text": "きょうもできたね"
}
```

`type` の候補:

- `finish`
- `reviewComplete`

レスポンス案:

- 成功時: `audio/mpeg` または `audio/wav`
- 失敗時: JSONでエラーを返す

失敗時レスポンス例:

```json
{
  "error": "tts_failed"
}
```

## 6. フロント側の実装方針

- `supportVoiceUsage.encouragement` が `true` のときだけ外部TTSを試す。
- 外部TTSに失敗したらWeb Speech API fallbackに戻す。
- 終了時・復習完了時だけWorkerを呼ぶ。
- 正解・不正解ごとには呼ばない。
- 連続再生しない。
- スマホの自動再生制約に注意する。
- 現在の短い声かけ文言の選択処理はできるだけ維持し、読み上げ部分だけ差し替えやすくする。

## 7. キャッシュ方針

PoCなので最初は複雑にしない。

- 同じ文言はWorker側またはブラウザ側でキャッシュできるとよい。
- ただし最初はキャッシュなしでもよい。
- 費用が気になる場合は、固定10文言を事前生成する案もあり。
- 事前生成する場合も、音声ファイルは公開してよい内容か確認してから配置する。

## 8. 同意・安全面

- すきな人のこえを使う場合は、話者本人の同意が必要。
- 保護者・家族・支援者の声を勝手に登録しない。
- 本人が安心できる声だけ使う。
- 録音音声をlocalStorageに保存しない方針は維持する。
- 外部APIへ送る内容は、終了時・復習完了時の短い固定文言に限定する。
- 学習履歴、名前、成績、個人情報は外部TTS APIへ送らない。

## 9. 実装ステップ案

1. Worker設計メモ作成
2. Workerの最小実装
3. フロントからWorkerを呼ぶ
4. 失敗時Web Speech API fallback
5. 終了時・復習完了時のみテスト
6. 必要なら固定文言の音声キャッシュ
7. 最後に声クローンを検討
